# Matched Metal hash and radix development evidence

All 96 case/build/round executions passed exact CPU parity, including full output order, payloads and nulls. Each retained seven alternating warm CPU/Metal samples, separate first-use collections and a separate native profile. The grid has 65,536 and 1,048,576 rows, four workloads, three input variants, two native builds and two rounds. Input construction and validation are outside caller-wall timings; allocation, staging, synchronization and complete materialization are included. Individual samples, host/compiler/library identities and all process output remain in `results.json` and `results/`. `results.md` contains the complete table.

The M1 Mac mini uses 16 GiB unified memory and eight CPU workers. Both native builds use the same freshly compiled Mojo benchmark and source execution revision `576ee8181bbba21f5a9db8170e85d547054c2be2`. The current native build is `ec16a3a0079af9a05a0ea1314d64a6ef96ad76f4123ec334ea55bd8e959328e6`; the preserved pre-hash/radix build is `0742b361ff93eae5b98dc4ed7bf9cfe9872bbc630dc2a24affa0847a5863faf9`. Their SHA-256 hashes are in the manifest. The benchmark files were overlaid onto the clean source checkout; their exact hashes identify that development harness. Profiles confirmed hash grouping, hash joins and integer radix sorting for all 48 current-build runs, and sorted joins for baseline join runs.

Across both rounds, hash joins were 1.40–1.98 times faster than the preserved path. Low-cardinality unsorted grouping improved 1.03–1.88 times; sorted grouping was 0.87–1.00 times baseline throughput. High-cardinality grouping was 0.92–0.95 times baseline throughput. Integer radix sorting was 0.76–0.94 times baseline throughput: it was slower in every selected case. Eligibility bounds are not established performance crossovers. These explicit accelerator mechanisms can regress, and automatic analytical placement excludes them.

These are development mechanisms, not external-suite or unseen-workload evidence. The current and preserved runtimes also differ in resident plumbing and buffer reuse; this comparison measures the complete native revision, not an isolated kernel-only algorithm change. No dispatch-bound tuning used these results. CPU versus Metal ratios in the full report are specific to these inputs, including CPU execution and materialization costs.
