# Apple Metal replacement coverage

This matrix tracks the incremental engine-replacement work in [#877](https://github.com/randyzwitch/dataframe_mojo/issues/877), part of the [Metal overhaul in #868](https://github.com/randyzwitch/dataframe_mojo/issues/868). It describes the **open PR #888 candidate** at [`6398713d`](https://github.com/randyzwitch/dataframe_mojo/commit/6398713df4a8f31268f5d6064d47d676b9d7bec1); it does not describe `main` as having adopted that candidate. CPU/Metal automatic placement remains deferred to [#583](https://github.com/randyzwitch/dataframe_mojo/issues/583).

“Legacy” below means the existing Metal route retained for compatibility while the new family-specific implementation is validated. PR #888 replaces only the direct row/scalar slices described below. All other operation families continue using the current Metal implementation and public APIs; they are not silently removed or newly supported by this change.

Separate prototypes for grouping, ordering, windows and native join inputs are not present in the PR #888 candidate. They are in progress and queued for Apple hardware validation; none is recorded here as having passed that gate. The earlier archived Int32 affine comparison is pinned to its own earlier candidate and is not evidence for the current PR head. The Int64/UInt64 archive above is pinned to `52efeb3a`, an ancestor of the PR #888 head, and remains a comparison for those recorded cases only.

## Retirement and validation gates

Keep a family on its current route until its replacement has exact, build-identified Apple-hardware evidence and all required contracts have a replacement. Each family needs public-query parity against the CPU plus independent typed/bitwise expectations where available; null, NaN and signed-zero cases; composed and shared-branch execution; checked-error/fault-order checks; metadata and exact/under-budget behavior; and complete-query timing against a frozen current-Metal baseline. Retain slow and failed cases with the receipts and qualification logs. Kernel-only timing does not satisfy the performance gate.

The pinned PR #888 focused gate passed its reported 14 groups, and the paired #889 archive validates all 144 recorded Int64/UInt64 benchmark workers. The native Linux checks for PR #888 head `6398713d` and PR #889 head `29890833` pass; other CI checks are pending. The separate broader candidate gate was **not all green**: selector expansion, categorical grouped row count and qcut whole-DAG synchronization differences were reproduced on the frozen baseline; an ordered profile/resource-bound failure received focused fixes and passing tests, but the broad gate was not rerun as all-green. The reports do not establish full-suite parity, close #877 or justify retiring untouched routes. Automatic CPU/Metal placement remains deferred under #583.
